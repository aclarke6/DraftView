# DraftView — PostgreSQL Query Standards

This document defines how to write PostgreSQL SQL that works correctly in this
project every time. These rules are mandatory for all agents and developers.

---

## The Core Rule: Case Sensitivity

PostgreSQL folds **unquoted** identifiers to lowercase. EF Core generates table
and column names in **PascalCase**. This mismatch is the single most common
source of query failures.

**Rule: always double-quote every table name and column name.**

```sql
-- WRONG — PostgreSQL lowercases these and finds nothing
SELECT MigrationId FROM __EFMigrationsHistory;

-- CORRECT
SELECT "MigrationId" FROM "__EFMigrationsHistory";
```

---

## Shell Escaping with `psql -c`

When running SQL via `psql -c '...'` from a shell prompt, the SQL string is
wrapped in **single quotes**. Double quotes for identifiers sit **inside** the
single-quoted string — no escaping needed.

```bash
# WRONG — backslash-escaping breaks the query
sudo -u postgres psql -d draftview -c 'SELECT \"MigrationId\" FROM \"__EFMigrationsHistory\"'

# CORRECT — single quotes wrap the whole SQL, double quotes inside for identifiers
sudo -u postgres psql -d draftview -c 'SELECT "MigrationId" FROM "__EFMigrationsHistory" ORDER BY "MigrationId";'
```

---

## Discover Table and Column Names

When unsure of the exact casing, use `\d` to inspect the table before writing
a query:

```bash
# List all tables
sudo -u postgres psql -d draftview -c '\dt'

# Describe a specific table (shows exact column names and types)
sudo -u postgres psql -d draftview -c '\d "__EFMigrationsHistory"'
```

## Quick Reference

```sql
-- Check applied EF migrations
SELECT "MigrationId", "ProductVersion"
FROM "__EFMigrationsHistory"
ORDER BY "MigrationId";

-- Count rows in a table
SELECT COUNT(*) FROM "AppUsers";

-- Find a user by email HMAC
SELECT "Id", "DisplayName", "Role", "IsActive"
FROM "AppUsers"
WHERE "EmailLookupHmac" = '<hmac>';

-- Check Identity users
SELECT "Id", "UserName", "Email"
FROM "AspNetUsers"
ORDER BY "UserName";
```

## The Three Things That Go Wrong

1. **No quotes** → `column "x" does not exist` — PostgreSQL lowercased your identifier
2. **Backslash-escaped quotes in shell** → `syntax error at or near "\""` — remove the backslashes; single-quote the whole SQL string and double-quote inside
3. **Wrong database name** → `FATAL: database "x" does not exist` — use `-d draftview`
